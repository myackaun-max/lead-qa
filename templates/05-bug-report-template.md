# Шаблон баг-репорту

```
ID:
Заголовок: [Модуль] Що зламано — де — за яких умов
Середовище: ОС / браузер і версія / пристрій / середовище (test, staging, prod) / версія збірки або commit
Передумови: (акаунт, роль, стан даних, фіче-флаги)
Кроки відтворення:
  1.
  2.
  3.
Тестові дані:
Фактичний результат:
Очікуваний результат: (з посиланням на вимогу, якщо є)
Severity: Critical | Major | Minor | Trivial
Priority: P1 | P2 | P3 | P4
Частота відтворення: завжди | N з M спроб | один раз
Докази: скріншот, відео, лог, HAR, запит/відповідь (curl), trace ID
Гіпотеза причини: (необов'язково)
Обхідний шлях: (якщо є)
Пов'язані: тест-кейс, вимога, інші баги
```

## Severity (вплив на продукт)
| Severity | Визначення | Приклад |
|---|---|---|
| Critical | Система або ключова функція недоступна, втрата чи пошкодження даних, вразливість безпеки, обхідного шляху немає | Оплата списує гроші, але замовлення не створюється |
| Major | Важлива функція працює неправильно, обхідний шлях складний | Фільтр за датою повертає неповні результати |
| Minor | Функція працює з незручностями, є простий обхідний шлях | Після збереження форма не скидається, треба оновити сторінку |
| Trivial | Косметика, не впливає на функціональність | Друкарська помилка, зсув іконки на 2px |

## Priority (терміновість виправлення)
| Priority | Коли виправляти |
|---|---|
| P1 | Негайно, блокує реліз або прод |
| P2 | У поточному спринті / до релізу |
| P3 | У наступних спринтах |
| P4 | Коли буде час / backlog |

Severity і priority незалежні: друкарська помилка в назві компанії на головній — Trivial, але P1.

## Приклад
```

Середовище: Windows 11 / Chrome 131 / staging / build 2.4.0-rc3 (a1b2c3d)
Передумови: користувач авторизований, у кошику 1 товар, тестова картка 4242 4242 4242 4242
Кроки відтворення:
  1. У DevTools увімкнути throttling «Slow 3G»
  2. Перейти до оплати, ввести дані картки
  3. Двічі швидко натиснути «Оплатити»
Фактичний результат: створено 2 транзакції по 500 грн, одне замовлення
Очікуваний результат: одна транзакція; кнопка блокується після першого натискання, бекенд відхиляє дублікат за Idempotency-Key
Severity: Critical   Priority: P1
Частота відтворення: 4 з 5 спроб
Докази: video.mp4, HAR, trace ID 7f3e…, лог платіжного сервісу
Гіпотеза причини: відсутня ідемпотентність на POST /payments
Обхідний шлях: немає для користувача; ручне повернення коштів підтримкою
```

## Чек-лист перед відправкою
- [ ] Відтворено ще раз на чистому стані
- [ ] Перевірено, що це не дублікат
- [ ] Заголовок зрозумілий без відкриття тікета
- [ ] Кроки мінімальні, розробник відтворить без питань
- [ ] Додано докази і версію збірки
